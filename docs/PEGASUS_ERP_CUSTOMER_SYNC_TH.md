# Engineering Center → Pegasus ERP: ขอ tool สำหรับดึงข้อมูลลูกค้า

ถึง: ทีม Pegasus ERP · จาก: ทีม Engineering Center (IoT Team application) · วันที่ 2026-10-28
อ้างอิง: `PURCHASE-REQUEST-MCP-TH.md` ที่ทีม ERP ส่งมา และ `PEGASUS_ERP_PR_INTEGRATION_TH.md`

AI agent ของทีม ERP อ่านไฟล์นี้ได้ทั้งไฟล์ การเรียก MCP (endpoint, header, JSON-RPC, การ map error) ใช้แบบเดียวกับการส่ง PR ใน `PEGASUS_ERP_PR_INTEGRATION_TH.md`

## สิ่งที่ต้องการ

- ให้ ERP เป็นต้นทางของข้อมูลลูกค้า และให้ Engineering Center ดึงมาอัปเดตต่อเนื่อง
- ตอนนี้ Sales สร้างลูกค้าเองใน Engineering Center ทีละราย รหัสลูกค้าเป็นรหัสที่แอปสร้างจากชื่อ ไม่ตรงกับรหัสใน ERP ข้อมูลสองฝั่งจึงไม่ตรงกัน
- เอกสาร MCP ห้ามระบบภายนอกผูกโค้ดกับ `erp_read` และ `erp_write` ฝั่งเราจึงขอ tool สำหรับเรื่องนี้โดยเฉพาะ
- ขอแบบอ่านอย่างเดียว ยังไม่ส่งข้อมูลลูกค้าจากแอปกลับเข้า ERP

## Tool ที่ขอ

ชื่อ tool เป็นข้อเสนอ ทีม ERP เปลี่ยนชื่อได้

### `customers_list`

ใช้ทั้งดึงครั้งแรกและดึงเฉพาะรายการที่เปลี่ยน

| Argument | ความหมาย |
|---|---|
| `updated_since` | ISO 8601 (UTC) ส่งลูกค้าที่สร้าง แก้ไข ปิดใช้งาน หรือรวมรายการหลังเวลานี้ ถ้าไม่ส่งให้คืนทั้งหมด |
| `cursor` | ค่าจากหน้าก่อน สำหรับหน้าถัดไป |
| `limit` | จำนวนต่อหน้า (เสนอค่าเริ่มต้น 200) |
| `include_inactive` | `true` ให้รวมลูกค้าที่ปิดใช้งานด้วย ใช้ตอนดึงแบบ `updated_since` เพื่อรู้ว่ารายใดถูกปิด |

คำตอบ: `{ "customers": [...], "next_cursor": "<ค่า หรือ null>", "server_time": "<ISO 8601>" }`
ฝั่งเราจะใช้ `server_time` เป็น `updated_since` ของรอบถัดไป จะไม่ใช้นาฬิกาของเราเอง

### `customer_get`

อ่านลูกค้ารายเดียวด้วย `customer_code` ใช้ตอนผูกลูกค้าเดิมของแอปกับลูกค้าใน ERP

## ฟิลด์ที่ขอต่อลูกค้าหนึ่งราย

| ฟิลด์ | ความหมาย |
|---|---|
| `customer_code` | รหัสลูกค้าใน ERP ใช้เป็น key ถาวร ไม่เปลี่ยนตลอดอายุลูกค้า |
| `name_th`, `name_en` | ชื่อบริษัทภาษาไทยและอังกฤษ |
| `short_name` | ชื่อย่อ ถ้ามี |
| `tax_id` | เลขประจำตัวผู้เสียภาษี 13 หลัก ใช้จับคู่กับลูกค้าที่มีอยู่แล้วในแอป |
| `branch` | สำนักงานใหญ่หรือเลขสาขา |
| `address`, `province`, `postal_code`, `country` | ที่อยู่ตามทะเบียน |
| `phone`, `email`, `website` | ช่องทางติดต่อของบริษัท ถ้ามี |
| `is_active` | ยังใช้งานอยู่หรือไม่ |
| `merged_into` | ถ้ารายการนี้ถูกรวมเข้ากับลูกค้ารายอื่น ให้ส่งรหัสลูกค้าปลายทาง ถ้าไม่ได้ถูกรวมให้เป็น `null` |
| `updated_at` | เวลาที่แก้ไขล่าสุดใน ERP |

ฟิลด์ที่ **ไม่ต้องการ**: วงเงินเครดิต เงื่อนไขการชำระเงิน ราคาขาย ส่วนลด และยอดค้างชำระ Engineering Center เก็บเฉพาะต้นทุนทางวิศวกรรม ไม่เก็บตัวเลขเชิงพาณิชย์

## สิ่งที่ฝั่ง Engineering Center จะทำ

1. เพิ่มรหัสลูกค้า ERP และเลขผู้เสียภาษีในตารางลูกค้าของเรา รหัสเดิมของแอปยังใช้ต่อ เพราะโครงการและเอกสารเก่าอ้างถึงอยู่
2. ดึงครั้งแรกแล้วจับคู่กับลูกค้าที่มีอยู่ ด้วยเลขผู้เสียภาษีก่อน แล้วจึงใช้ชื่อ รายการที่จับคู่ไม่ชัดจะให้ Admin ยืนยันเองบนหน้าจอ ระบบจะไม่รวมรายการเอง
3. ลูกค้าที่ผูกกับ ERP แล้วจะแก้ชื่อ เลขผู้เสียภาษี และที่อยู่ในแอปไม่ได้ ต้องแก้ใน ERP ส่วนผู้ติดต่อ Site ผู้ดูแลลูกค้า และชื่อภาษาญี่ปุ่นยังแก้ในแอปได้ตามเดิม
4. ลูกค้าที่ Sales สร้างในแอประหว่างที่ ERP ยังไม่มี (ลูกค้าใหม่ที่ยังอยู่ช่วงเสนองาน) ยังสร้างในแอปได้ และจะผูกกับ ERP เมื่อ ERP เปิดลูกค้ารายนั้นแล้ว
5. ลูกค้าที่ ERP ปิดใช้งานหรือรวมเข้ากับรายอื่น จะถูกปิดหรือชี้ไปยังรายปลายทางในแอป ระบบจะไม่ลบข้อมูล

## สิ่งที่ต้องการคำตอบจากทีม ERP

1. **Token สำหรับดึงข้อมูลเบื้องหลัง** (ข้อสำคัญที่สุด)
   - การ sync ต่อเนื่องต้องดึงเป็นรอบ แม้ไม่มีใครเปิดแอปอยู่ แต่ MCP ตอนนี้รับเฉพาะ access token ของผู้ใช้ และไม่รับ service account หรือ `client_credentials`
   - ขอให้เลือกทางใดทางหนึ่ง:
     - (ก) อนุญาต `client_credentials` ให้ client ของเรา จำกัดให้ใช้ได้เฉพาะ tool ลูกค้าแบบอ่านอย่างเดียว เราจะดึงทุก 15 นาที
     - (ข) คงการใช้ token ของผู้ใช้ไว้ เราจะดึงเฉพาะเมื่อมีคนเปิดหน้าลูกค้าหรือค้นหาลูกค้า ไม่เกิน 1 ครั้งต่อ 15 นาที แบบเดียวกับการอ่านสถานะ PR ข้อเสียคือถ้าไม่มีใครเปิดหน้านั้น ข้อมูลจะไม่อัปเดต
   - ถ้าเลือก (ข) ช่วยแจ้งว่าพนักงานคนไหนมีสิทธิ์อ่านรายชื่อลูกค้าบ้าง
2. **รหัสลูกค้า** `customer_code` เปลี่ยนได้ไหม ถ้าเปลี่ยนได้ ขอ id ถาวรเพิ่มอีกหนึ่งฟิลด์
3. **ลูกค้าที่ถูกลบหรือรวมรายการ** ERP ลบลูกค้าจริงหรือแค่ปิดใช้งาน และกรณีที่รวมลูกค้าซ้ำ ERP บันทึกไว้อย่างไร
4. **จำนวนลูกค้า** ตอนนี้มีประมาณกี่ราย เพื่อกำหนด `limit` ต่อหน้าที่เหมาะสม
5. **ชื่อภาษาญี่ปุ่น** ERP เก็บไว้ไหม ถ้าเก็บขอเพิ่ม `name_ja`
6. **ที่อยู่หลายแห่ง** ERP แยกที่อยู่ตามทะเบียนกับที่อยู่ส่งของไหม เราต้องการแค่ที่อยู่ตามทะเบียน ส่วนสถานที่ติดตั้งยังเก็บที่ Site ของแอป
7. **Rate limit** ของ tool ใหม่ใช้ค่าเดียวกับ tool จัดซื้อหรือไม่
