# Engineering Center → Pegasus ERP: ขอ tool สำหรับดึงข้อมูลลูกค้าและซัพพลายเออร์

ถึง: ทีม Pegasus ERP · จาก: ทีม Engineering Center (IoT Team application) · วันที่ 2026-11-02
อ้างอิง: `PURCHASE-REQUEST-MCP-TH.md` (2026-10-27) ข้อ 1.1, 5 และ 8.4

AI agent ของทีม ERP อ่านไฟล์นี้ได้ทั้งไฟล์ การเรียก MCP (endpoint, header, JSON-RPC, การ map error) ใช้แบบเดียวกับการส่ง PR ใน `PEGASUS_ERP_PR_INTEGRATION_TH.md`

## สรุปสั้น

- ต้องการให้ ERP เป็นต้นทางของทะเบียนลูกค้าและทะเบียนซัพพลายเออร์ และให้ Engineering Center ดึงมาอัปเดตอย่างต่อเนื่อง ขอแบบอ่านอย่างเดียว ไม่ส่งข้อมูลจากแอปกลับเข้า ERP
- **ลูกค้า:** เอกสาร MCP ข้อ 8.4 ระบุว่าทีม ERP วางแผนทำ tool "ดึงรายชื่อลูกค้า" ไว้แล้ว ไฟล์นี้เสนอรูปแบบที่ฝั่งเราต้องใช้
- **ซัพพลายเออร์:** `purchasing_suppliers_list` เป็นช่องค้นหา ส่งกลับเฉพาะ `supplier_id` กับ `supplier_name` ครั้งละไม่เกิน 30 ราย และเฉพาะซัพที่อนุมัติแล้ว จึงใช้ดึงทะเบียนซัพทั้งชุดไม่ได้ ขอ tool อ่านทะเบียนเพิ่มอีกหนึ่งตัว

## ทำไมต้องดึงจาก ERP

- **ลูกค้า:**
  - Sales สร้างลูกค้าเองในแอปทีละราย รหัสลูกค้าเป็นรหัสที่แอปสร้างจากชื่อ จึงไม่ตรงกับ ERP
  - ทีม ERP ตอบเรื่อง Cost Sheet ไว้ว่า `customer` จะผูกกับลูกค้าใน ERP ก็ต่อเมื่อชื่อตรงกันทุกตัวอักษร ถ้าชื่อในแอปสะกดต่างไปแม้เล็กน้อย Cost Sheet จะไม่ผูกกับลูกค้า
- **ซัพพลายเออร์:**
  - แอปสร้างซัพเองตอนนำเข้าใบเสนอราคา PDF
  - ถ้าแอปมี `supplier_id` ของ ERP ฝั่งเราจะส่ง `suggested_supplier_id` และ `quotes[].supplier_id` ใน PR ได้ ERP ไม่ต้องเดาซัพจากชื่ออีก

## วิธีดึงที่ฝั่งเราจะใช้

ทำตามข้อ 1.1 ที่ห้ามมีงานเบื้องหลังเรียก ERP แทนผู้ใช้

- ดึงเมื่อมีคนเปิดหน้าลูกค้าหรือหน้าซัพ หรือค้นหาลูกค้าหรือซัพในแอป และใช้ token ของคนนั้น
- ข้อมูลทะเบียนเหมือนกันสำหรับทุกคน จึงดึงไม่เกิน 1 รอบต่อ 15 นาทีสำหรับทั้งระบบ ไม่ได้นับแยกรายคน
- ครั้งแรกดึงทั้งชุดทีละหน้า หลังจากนั้นดึงเฉพาะรายการที่เปลี่ยน (`updated_since`)
- หน้าละ 200 รายการ จำนวนครั้งที่เรียกจึงต่ำกว่าเพดาน 120 ครั้งต่อนาทีต่อผู้ใช้มาก

## Tool ที่ขอ

ชื่อ tool และชื่อฟิลด์เป็นข้อเสนอ ทีม ERP เปลี่ยนได้

| Tool | ใช้ทำอะไร |
|---|---|
| `customers_list` | อ่านทะเบียนลูกค้าทีละหน้า ใช้ทั้งดึงครั้งแรกและดึงเฉพาะที่เปลี่ยน |
| `customer_get` | อ่านลูกค้ารายเดียวด้วย `customer_code` ใช้ตอนผูกลูกค้าเดิมของแอป |
| `suppliers_list` | อ่านทะเบียนซัพทีละหน้า แบบเดียวกับ `customers_list` ส่วน `purchasing_suppliers_list` ยังใช้ค้นหาตามเดิม |

Argument ของ `customers_list` และ `suppliers_list`:

| Argument | ความหมาย |
|---|---|
| `updated_since` | ISO 8601 (UTC) ส่งรายการที่สร้าง แก้ไข ปิดใช้งาน หรือรวมรายการหลังเวลานี้ ถ้าไม่ส่งให้คืนทั้งหมด |
| `cursor` | ค่าจากหน้าก่อน สำหรับหน้าถัดไป |
| `limit` | จำนวนต่อหน้า (เสนอค่าเริ่มต้น 200) |
| `include_inactive` | `true` ให้รวมรายการที่ปิดใช้งานด้วย ใช้ตอนดึงแบบ `updated_since` เพื่อรู้ว่ารายใดถูกปิด |

คำตอบ: `{ "customers": [...] หรือ "suppliers": [...], "next_cursor": "<ค่า หรือ null>", "server_time": "<ISO 8601>" }`
ฝั่งเราจะใช้ `server_time` เป็น `updated_since` ของรอบถัดไป จะไม่ใช้นาฬิกาของเราเอง

## ฟิลด์ที่ขอ

### ลูกค้า

| ฟิลด์ | ความหมาย |
|---|---|
| `customer_code` | รหัสลูกค้าใน ERP ใช้เป็น key ถาวร ไม่เปลี่ยนตลอดอายุลูกค้า |
| `name_th`, `name_en` | ชื่อบริษัทภาษาไทยและอังกฤษ |
| `short_name` | ชื่อย่อ ถ้ามี |
| `tax_id` | เลขประจำตัวผู้เสียภาษี 13 หลัก ใช้จับคู่กับลูกค้าที่มีอยู่แล้วในแอป |
| `branch` | สำนักงานใหญ่หรือเลขสาขา |
| `address`, `province`, `postal_code`, `country` | ที่อยู่ตามทะเบียน |
| `phone`, `email`, `website` | ช่องทางติดต่อของบริษัท ถ้ามี |
| `is_active` | ยังใช้งานอยู่หรือไม่ |
| `merged_into` | ถ้ารายการนี้ถูกรวมเข้ากับลูกค้ารายอื่น ให้ส่งรหัสของรายปลายทาง ถ้าไม่ได้ถูกรวมให้เป็น `null` |
| `updated_at` | เวลาที่แก้ไขล่าสุดใน ERP |

### ซัพพลายเออร์

| ฟิลด์ | ความหมาย |
|---|---|
| `supplier_id` | id เดียวกับที่ `purchasing_suppliers_list` และ `quotes[].supplier_id` ใช้ |
| `supplier_code` | รหัสซัพใน ERP ถ้ามี |
| `name_th`, `name_en` | ชื่อบริษัทภาษาไทยและอังกฤษ |
| `tax_id` | เลขประจำตัวผู้เสียภาษี ใช้จับคู่กับซัพที่มีอยู่แล้วในแอป (แอปเก็บเลขนี้จากใบเสนอราคาอยู่แล้ว) |
| `branch` | สำนักงานใหญ่หรือเลขสาขา |
| `address`, `province`, `postal_code`, `country` | ที่อยู่ตามทะเบียน |
| `phone`, `email`, `website`, `contact_name` | ช่องทางติดต่อและผู้ติดต่อหลัก ถ้ามี |
| `approval_status` | อนุมัติแล้ว หรือรออนุมัติ |
| `is_active`, `merged_into`, `updated_at` | ความหมายเดียวกับฝั่งลูกค้า |

ฟิลด์ที่ **ไม่ต้องการ**: บัญชีธนาคาร วงเงินเครดิต เงื่อนไขการชำระเงิน ราคาขาย ส่วนลด ยอดซื้อขาย และยอดค้างชำระ Engineering Center เก็บเฉพาะต้นทุนทางวิศวกรรม ไม่เก็บตัวเลขเชิงพาณิชย์

## สิ่งที่ฝั่ง Engineering Center จะทำ

1. เพิ่มรหัส ERP ในตารางลูกค้าและตารางซัพของเรา และเพิ่มเลขผู้เสียภาษีในตารางลูกค้า (ตารางซัพมีอยู่แล้ว) รหัสเดิมของแอปยังใช้ต่อ เพราะโครงการและเอกสารเก่าอ้างถึงอยู่
2. ดึงครั้งแรกแล้วจับคู่กับรายการที่มีอยู่ ด้วยเลขผู้เสียภาษีก่อน แล้วจึงใช้ชื่อ รายการที่จับคู่ไม่ชัดจะให้ Admin ยืนยันเองบนหน้าจอ ระบบจะไม่รวมรายการเอง
3. รายการที่ผูกกับ ERP แล้วจะแก้ชื่อ เลขผู้เสียภาษี และที่อยู่ในแอปไม่ได้ ต้องแก้ใน ERP ส่วนข้อมูลที่มีเฉพาะในแอปยังแก้ได้ตามเดิม ได้แก่ ผู้ติดต่อ Site ผู้ดูแลลูกค้า และชื่อภาษาญี่ปุ่นของลูกค้า กับยี่ห้อและหมวดของซัพ
4. ลูกค้าใหม่ที่ยังอยู่ช่วงเสนองาน และซัพใหม่จากใบเสนอราคาที่ ERP ยังไม่มี ยังสร้างในแอปได้ แอปจะแสดงว่า "ยังไม่อยู่ใน ERP" และผูกให้เมื่อ ERP เปิดรายการนั้นแล้ว
5. รายการที่ ERP ปิดใช้งานหรือรวมเข้ากับรายอื่น จะถูกปิดหรือชี้ไปยังรายปลายทางในแอป ระบบจะไม่ลบข้อมูล
6. ช่วงถัดไป เมื่อซัพผูกกับ ERP แล้ว PR ที่ส่งเข้า ERP จะแนบ `supplier_id` ไปด้วย

## สิ่งที่ต้องการคำตอบจากทีม ERP

1. **สิทธิ์อ่านทะเบียน** role ไหนอ่านลูกค้าและซัพได้บ้าง เช่น STAFF อ่านได้ไหม
   - ฝั่งเราจะดึงด้วย token ของคนที่เปิดหน้า ถ้าวิศวกรทั่วไปไม่มีสิทธิ์ ข้อมูลจะอัปเดตเฉพาะตอนที่คนที่มีสิทธิ์ (เช่น Sales หรือ Admin) เปิดหน้านั้น
   - ช่วยยืนยันด้วยว่าวิธีดึงตอนผู้ใช้เปิดหน้า โดยไม่มีงานเบื้องหลัง ตรงกับกติกาข้อ 1.1
2. **Key ถาวร** `customer_code` และ `supplier_id` เปลี่ยนได้ไหม ถ้าเปลี่ยนได้ ขอ id ถาวรเพิ่มอีกหนึ่งฟิลด์
3. **การลบและรวมรายการ** ERP ลบจริงหรือแค่ปิดใช้งาน และกรณีรวมรายการซ้ำ ERP บันทึกไว้อย่างไร
4. **จำนวน** ตอนนี้มีลูกค้าและซัพประมาณกี่ราย เพื่อกำหนด `limit` ต่อหน้าที่เหมาะสม
5. **ชื่อภาษาญี่ปุ่น** ERP เก็บชื่อลูกค้าภาษาญี่ปุ่นไหม ถ้าเก็บขอเพิ่ม `name_ja`
6. **ที่อยู่หลายแห่ง** ERP แยกที่อยู่ตามทะเบียนกับที่อยู่ส่งของไหม เราต้องการเฉพาะที่อยู่ตามทะเบียน ส่วนสถานที่ติดตั้งยังเก็บที่ Site ของแอป
7. **ผูก Cost Sheet ด้วยรหัสลูกค้า** เมื่อแอปมี `customer_code` แล้ว `cost_estimate_submit` จะรับ `customer_code` แทนการเทียบชื่อได้ไหม
8. **ซัพที่รออนุมัติ** `suppliers_list` ส่งซัพที่ยังรออนุมัติมาด้วย (พร้อม `approval_status`) ได้ไหม เพื่อให้แอปรู้ว่าซัพจากใบเสนอราคารออนุมัติอยู่ใน ERP แล้ว
