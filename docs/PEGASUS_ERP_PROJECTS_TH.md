# Engineering Center → Pegasus ERP: ขอ tool สำหรับดึงทะเบียนโปรเจกต์

ถึง: ทีม Pegasus ERP · จาก: ทีม Engineering Center (IoT Team application) · วันที่ 2026-11-06
อ้างอิง: `PURCHASE-REQUEST-MCP-TH.md` (2026-10-27) ข้อ 3.1, 5 และ 8.4 และ `PEGASUS_ERP_CUSTOMER_SUPPLIER_SYNC_TH.md`
สถานะ (2026-11-06): ฝั่งเราใช้ `purchasing_projects_list` ค้นเลขโปรเจกต์ตอนพิมพ์ได้แล้ว ส่วน tool ที่ขอในเอกสารนี้ยังรอทีม ERP

AI agent ของทีม ERP อ่านไฟล์นี้ได้ทั้งไฟล์ การเรียก MCP (endpoint, token, JSON-RPC, การ map error) ใช้แบบเดียวกับการส่ง PR ใน `PEGASUS_ERP_PR_INTEGRATION_TH.md`

## สรุปสั้น

- ต้องการให้ ERP เป็นต้นทางของทะเบียนโปรเจกต์ และให้ Engineering Center ดึงมาได้ทั้งชุดแบบเดียวกับ `customers_list` ขออ่านอย่างเดียว ไม่ส่งข้อมูลจากแอปกลับเข้า ERP
- ตอนนี้มีแค่ `purchasing_projects_list` ซึ่งเป็นช่องค้นหา ได้ไม่เกิน 30 รายการต่อครั้ง และส่งกลับแค่เลข ชื่อโปรเจกต์ และชื่อลูกค้า ใช้ตรวจเลขตอนพิมพ์ได้ แต่ใช้ดึงทะเบียนทั้งชุดหรือรู้สถานะของโปรเจกต์ไม่ได้
- ขอเพิ่มสอง tool: `projects_list` และ `project_get`
- **ไม่ขอข้อมูลมูลค่า** เช่น มูลค่าสัญญา ราคาขาย หรือกำไร แอปนี้เก็บเฉพาะต้นทุนงานวิศวกรรม ขอให้ไม่ส่งฟิลด์เหล่านี้มาเลย

## ทำไมต้องดึงจาก ERP

- วิศวกรสร้างโปรเจกต์ในแอปเมื่อได้ PO แล้วพิมพ์เลขโปรเจกต์ (เช่น `PJ260172`) เอง ถ้าพิมพ์ผิด ERP จะไม่รับ PR ใบนั้น (`project_no`: "Project not found.")
- โปรเจกต์ที่ ERP ยังไม่ออกเลข ฝั่งเราใส่เลขชั่วคราว `PJ000000` ไว้ก่อน PR และ Cost Sheet ของโปรเจกต์เหล่านี้เข้า ERP โดยไม่ผูกโปรเจกต์ เมื่อ ERP ออกเลขแล้ว ต้องมีคนกลับมาเปลี่ยนเลขในแอปเอง
- เอกสาร MCP ข้อ 8.4 ระบุว่าทีม ERP วางแผนทำ "ให้ ERP แจ้งเลขโปรเจกต์อัตโนมัติเมื่อใบเสนอราคาอนุมัติ" ไว้แล้ว tool ในเอกสารนี้คือรูปแบบที่ฝั่งเราอ่านได้โดยไม่ต้องมี background job: แอปดึงตอนมีคนเปิดหน้าโปรเจกต์ ด้วย token ของคนนั้น เหมือนการดึงลูกค้า

## สิ่งที่ฝั่ง Engineering Center ทำแล้ว (2026-11-06)

- **ช่องเลขโปรเจกต์ค้น ERP:** ในหน้าสร้างโปรเจกต์ และในหน้าแก้ไขโปรเจกต์ของโปรเจกต์ที่ยังใช้ `PJ000000`
  - พิมพ์เลข ชื่อโปรเจกต์ หรือชื่อลูกค้า แล้ว backend เรียก `purchasing_projects_list` ด้วย `{"q": "<ที่พิมพ์>"}` และ token TMT ID ของคนที่พิมพ์
  - เรียกหลังหยุดพิมพ์ 400 ms ครั้งละหนึ่งคำค้น ต่ำกว่า 120 ครั้งต่อนาทีต่อคนมาก
  - เลือกจากรายการแล้วแอปใส่เลขตามที่ ERP สะกด ถ้าสร้างโปรเจกต์แบบไม่มี Estimate แอปเติมชื่อโปรเจกต์และลูกค้าให้ด้วย (เมื่อชื่อลูกค้าตรงกับลูกค้าในแอปรายเดียว)
  - ใต้ช่องบอกว่าพบเลขนี้ใน ERP, ไม่พบ, หรือมีโปรเจกต์อื่นในแอปใช้เลขนี้แล้ว ถ้า ERP ตอบไม่ได้ ยังพิมพ์เลขเองได้ตามเดิม
- **เปลี่ยนเลขชั่วคราวเป็นเลขจริง:** โปรเจกต์ที่ใช้ `PJ000000` เปลี่ยนเป็นเลขจาก ERP ได้หนึ่งครั้งในหน้าแก้ไขโปรเจกต์ เลขจริงแล้วเปลี่ยนอีกไม่ได้ เพราะ PR และ Cost Sheet ส่งเข้า ERP ด้วยเลขนั้นไปแล้ว

## Tool ที่ขอ

| tool | ใช้ทำอะไร |
|---|---|
| `projects_list` | อ่านทะเบียนโปรเจกต์ทีละหน้า ใช้ทั้งดึงครั้งแรกและดึงเฉพาะที่เปลี่ยน รูปแบบเดียวกับ `customers_list` |
| `project_get` | อ่านโปรเจกต์รายเดียวด้วย `project_id` หรือ `project_no` ใช้ตอนเปิดดูโปรเจกต์ในแอป |

Argument ของ `projects_list` (เหมือน `customers_list`):

| argument | ความหมาย |
|---|---|
| `limit` | จำนวนต่อหน้า ฝั่งเราจะส่ง 200 |
| `cursor` | `next_cursor` จากหน้าก่อน |
| `updated_since` | เวลา `server_time` จากหน้าแรกของรอบก่อน ส่งกลับเฉพาะที่เปลี่ยนหลังเวลานั้น รวมที่ถูกยกเลิกหรือปิด |
| `include_inactive` | `true` เพื่อให้ได้โปรเจกต์ที่ยกเลิกหรือปิดแล้วด้วย |

ผลตอบกลับ: `{"projects": [...], "next_cursor": "..." | null, "server_time": "..."}`

## ฟิลด์ที่ขอ

| ฟิลด์ | ความหมาย |
|---|---|
| `project_id` | id ถาวรของโปรเจกต์ ไม่เปลี่ยนตลอดอายุ (ถ้า `project_no` แก้ได้ ฝั่งเราจะใช้ฟิลด์นี้เป็น key แบบเดียวกับ `customer_id`) |
| `project_no` | เลขโปรเจกต์ เช่น `PJ260172` ตัวพิมพ์ตามที่ `purchase_request_create` ต้องการ |
| `project_name` | ชื่อโปรเจกต์ |
| `customer_id`, `customer_code`, `customer_name` | ลูกค้าของโปรเจกต์ `customer_id` ตรงกับที่ `customers_list` ส่งมา ฝั่งเราผูกลูกค้าด้วย id นี้ |
| `status` | สถานะในรูปรหัส เช่น `OPEN`, `CLOSED`, `CANCELLED` พร้อม `status_label` |
| `quotation_no` | เลขใบเสนอราคาที่เปิดโปรเจกต์ ถ้ามี ใช้จับคู่กับ Estimate ในแอป |
| `customer_po_no`, `customer_po_date` | เลข PO และวันที่ PO ของลูกค้า ถ้ามี |
| `start_date`, `end_date` | วันเริ่มและวันจบตามแผนใน ERP ถ้ามี |
| `manager_email` | อีเมลของผู้รับผิดชอบโปรเจกต์ใน ERP ถ้ามี ใช้จับคู่กับพนักงานในแอป |
| `created_at`, `updated_at` | เวลาสร้างและแก้ล่าสุด (ISO 8601) |

ไม่ต้องส่ง: มูลค่าสัญญา ราคาขาย ต้นทุนรวม กำไร หรือมูลค่าใด ๆ ที่เป็นตัวเลขทางการค้า

## สิ่งที่ฝั่ง Engineering Center จะทำเมื่อมี tool

- ดึงแบบเดียวกับลูกค้า: ตอนมีคนเปิดหน้าโปรเจกต์ ด้วย token ของคนนั้น ทั้งระบบไม่เกิน 1 รอบต่อ 15 นาที ไม่มีงานเบื้องหลัง
- โปรเจกต์ในแอปที่ยังใช้ `PJ000000` และตรงกับโปรเจกต์ใน ERP (ด้วยเลขใบเสนอราคา หรือลูกค้ากับเลข PO) ได้เลขจริงเอง ถ้าไม่ชัดให้ Admin หรือ PM ยืนยัน
- ช่องเลขโปรเจกต์ตอนสร้างโปรเจกต์ค้นจากทะเบียนที่ดึงไว้แทนการเรียก ERP ทุกครั้งที่พิมพ์
- โปรเจกต์ที่ ERP ยกเลิกแสดงเตือนในแอป ไม่ปิดหรือลบโปรเจกต์ในแอปเอง

## สิ่งที่ต้องการคำตอบจากทีม ERP

1. **เอกสาร MCP ฉบับล่าสุด:** คำตอบเรื่องลูกค้า (2026-11-04) อ้างข้อ 10 ของเอกสาร MCP ฉบับที่ฝั่งเรามีคือ 2026-10-27 ซึ่งยังไม่มีข้อ 10 ขอฉบับล่าสุด ถ้ามี tool ของโปรเจกต์อยู่แล้ว ฝั่งเราจะใช้ตามนั้นแทนที่ขอในเอกสารนี้
2. **Key ถาวร:** `project_no` แก้ได้ไหม ถ้าแก้ได้ขอ `project_id`
3. **สิทธิ์:** วิศวกร (role `STAFF`) เรียก `projects_list` ด้วย token ของตัวเองได้ไหม และเห็นทุกโปรเจกต์หรือเฉพาะบางแผนก
4. **เลขโปรเจกต์อัตโนมัติ (ข้อ 8.4):** ERP ออกเลขโปรเจกต์ตอนไหน และผูกกับใบเสนอราคาหรือ PO อย่างไร ฝั่งเราจะใช้ข้อมูลนี้จับคู่โปรเจกต์ `PJ000000`
5. **สถานะ:** มีสถานะอะไรบ้าง และสถานะไหนที่ยังรับ PR ได้ (ข้อ 3.1 ระบุว่าเฉพาะ `CANCELLED` ที่ไม่รับ)
6. **`purchasing_projects_list`:** ค้นด้วย `customer_name` แล้วได้โปรเจกต์ของลูกค้านั้นเรียงจากล่าสุดไหม และถ้าไม่ส่ง `q` ได้ 30 รายการล่าสุดหรือไม่
